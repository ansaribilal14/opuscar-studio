SECTION 1 — NON-NEGOTIABLE EXECUTION RULES

1.1 GitHub is the durable source of truth

The Z Super execution server is session-sensitive and may be reset, disconnected, or completely wiped.

Never assume that local files, terminal sessions, environment state, running processes, or conversational context will survive.

Follow these rules throughout the entire task:

1. Inspect the current repository, branch, remotes, commit history, working tree, and remote synchronization state before making changes.
2. Fetch the latest remote state and inspect all uncommitted work before switching branches or modifying files.
3. Never overwrite or discard unknown user changes.
4. Create or use a dedicated feature branch and preferably an isolated Git worktree or clone.
5. Commit each coherent, validated milestone and push it to the correct remote branch immediately.
6. Verify the remote commit hash after each significant push.
7. Never rely on an unpushed local commit as the only backup.
8. Never use repeated "git checkout -f", destructive resets, forced branch changes, or similar operations to work around unexpected environment changes.
9. Before writing, committing, pushing, or publishing, verify that the repository and branch are the intended ones.
10. If the branch unexpectedly changes, stop writing immediately, preserve the current work, inspect the actual Git state, and recover safely.
11. Never commit secrets, credentials, tokens, caches, "node_modules", temporary files, or inappropriate generated media.
12. Never claim that code is saved, pushed, released, tested, or complete unless actual tool output verifies that claim.

If GitHub access is unavailable, preserve the local state and document the blocker. Resume synchronization when access returns.

SECTION 4 — THE DOCUMENTARY

4.1 Title

THE WOW! SIGNAL — 72 Seconds from Deep Space

Channel: The Unclosed File
Language: English
Genre: Scientific mystery / space documentary
Format: Full-length narrated documentary
Target duration: 10 minutes

4.2 Editorial objective

Produce a polished, suspenseful, evidence-led documentary about the 1977 Wow! Signal.

The documentary should explain what was detected, why the signal attracted attention, what the famous annotation meant, what follow-up observations established, and why the origin remains unresolved.

It must be scientifically responsible. Do not imply that extraterrestrial intelligence caused the signal, that aliens were detected, or that a hypothesis has been proven when the evidence does not support that claim.

The film should feel like a carefully directed documentary rather than a generic slideshow or a series of static text cards.

4.3 Historical research and fact-checking

Before writing the final script, research the historical and scientific facts using authoritative sources.

Prioritize:

- The Big Ear Observatory and Ohio State University historical resources.
- Original scientific papers and documented follow-up observations.
- SETI Institute resources.
- Reputable astronomy institutions and scientific publications.
- NASA resources where directly relevant.
- Reliable primary or archival sources for Jerry Ehman and the original observation.

For every significant factual claim, record its source and supporting reference in the research notes.

Distinguish clearly between:

- Confirmed historical observations.
- The signal's measured properties.
- Scientific interpretations.
- Proposed explanations.
- Unresolved questions.

Do not repeat unsupported internet folklore as established fact.

If sources disagree, document the disagreement and use appropriately qualified wording in the script.

Create:

- "RESEARCH.md"
- "SOURCE_NOTES.md"
- "FACT_CHECK.md"
- "SCRIPT.md"
- "STORYBOARD.md"

The research documentation must be committed to the repository.

SECTION 5 — FULL TEN-MINUTE REQUIREMENT

Each engine must produce a complete approximately 10-minute documentary.

A short preview, trailer, teaser, proof of concept, or 75-second sample does not satisfy this task.

Target technical specification

- Duration: 10:00 minutes.
- Acceptable duration: 9:59–10:01, unless an alternative is explicitly approved.
- Resolution: 1920 × 1080.
- Aspect ratio: 16:9.
- Frame rate: 30 fps.
- Target frame count: approximately 18,000 frames.
- Container: MP4.
- Video codec: H.264.
- Target pixel format: yuv420p.
- Audio: stereo AAC.
- Narration: one shared English narration recording.
- Captions: identical English subtitle wording and timing.
- Ending: identical closing card, branding, and credits.

If an engine has a documented technical limitation, record it and attempt a compliant export or transparent normalization step. Do not silently weaken the delivery specification.

Use the same narration and subtitle timing for all three videos.

Narration duration gate

A natural 10-minute narration generally requires a substantial script, often approximately 1,200–1,450 words depending on pacing, pauses, and delivery style.

Use the actual prepared audio duration as the final authority.

Do not artificially extend a short script with silence, repeated paragraphs, or empty scenes just to reach 10 minutes.

Before rendering:

1. Complete and fact-check the script.
2. Generate or record the shared narration.
3. Measure the actual narration duration.
4. Prepare the subtitle file from the final script and actual timing.
5. Freeze the timeline and audio manifests.
6. Verify that the complete edit supports the target duration naturally.

If the narration is too short, revise the content meaningfully before freezing the creative specification.
